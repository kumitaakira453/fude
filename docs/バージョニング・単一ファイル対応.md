# バージョニング・単一ファイル対応 実装指示書

## 目的

fude に、次の2つを追加する。

1. Markdown ファイルの手動バージョニング
2. フォルダを指定しなくても、単一の Markdown ファイルを開く／新規メモを始める機能

どちらも別アプリ・別エディタとして作らない。既存の本文編集、レビュー、CLI、リアルタイム反映を共通利用する。

fude の中心概念は「Markdown フォルダを開くアプリ」から「Markdown 文書を読み、編集し、版とレビューを扱うワークベンチ」へ広げる。

## 現状の前提

実装前に以下を確認すること。

- `src-tauri/src/review/snapshot.rs` に内容ハッシュによるスナップショット保存がある。
- `src-tauri/src/review/store.rs` に `Ledger` / `Version` / `Origin` がある。
- `Origin::Comment` はレビュー開始時点、`Origin::Commit` は AI の対応完了時点を表す。
- `Origin::Checkpoint` は人間が明示的に版を保存する用途として定義済みだが、一般UIからは未使用である。
- `fude review commit` と `fude review versions` は既存CLIとして動いている。既存CLIの挙動を壊さない。
- GUI と CLI は同じ台帳を読む。台帳はロック取得と一時ファイル経由の atomic rename で更新する。
- 現在の編集は `useWorkspace.ts` の自動保存と `DocPane.tsx` の編集状態を中心に動いている。
- 外部編集との3者マージは未実装である。保存前の競合検知を必ず考慮する。

既存の「内容ハッシュ + スナップショット + 台帳」を利用し、MVPのためにGitリポジトリを埋め込まない。

## スコープ

### 今回実装するもの

- 現在の本文を手動で版として保存する
- 版の一覧を表示する
- 現在の本文と過去版の差分を表示する
- 任意の2版の差分を表示する
- 過去版から現在のファイルを復元する
- 復元前の現在本文を自動保存する
- フォルダを指定せずに既存のMarkdownファイルを開く
- 保存先未定の新規メモを作成する
- 新規メモをアプリ内部の一時領域へ自動保存する
- 「名前を付けて保存」で新しい保存先へ移動する
- 単一ファイルでも編集・レビュー・版管理を利用できる

### 今回実装しないもの

- 複数ファイルをまたぐGit風コミット
- ブランチ、マージ、rebase
- GitHubへの直接push、commit、PR作成
- 複数文書を常時開くタブ管理
- タグ付きノートデータベース
- Markdown以外のファイル形式
- 完全な外部編集3者マージ

外部編集の完全な合流は別タスクとする。ただし、今回の保存・復元処理で外部変更を無言で上書きしてはならない。

## バージョニング仕様

### 基本単位

MVPでは1ファイル単位で履歴を持つ。版は本文全体のスナップショットであり、差分は版と版の間で計算する。

版には最低限、次の情報を持つ。

- `id`: 本文内容のSHA-256ハッシュ
- `file`: 既存の台帳互換の文書識別子
- `label`: ユーザーまたはAIが付けた説明
- `origin`: `comment` / `commit` / `checkpoint`
- `created_at`: 作成時刻

同じファイル・同じ内容の版は重複保存しない。既存版に新しいラベルを付ける場合は、既存レコードのラベルを更新する既存方針を維持する。

### 手動保存

本文画面から「版を保存」を実行できるようにする。

- ラベルは任意入力とする
- 未入力時は日時を表示上の既定ラベルにする
- 保存対象は画面上の現在本文とする
- 自動保存のたびに版を作らない
- 同じ内容なら新しいスナップショットを作らない
- 手動保存の版は `Origin::Checkpoint` とする

既存の `review commit` はAIによる対応完了を記録するコマンドなので、一般UIの手動保存とは意味を分ける。既存CLIの名前と意味は変更しない。

### 履歴表示

履歴パネルには、対象ファイルの版を新しい順に表示する。

- ラベル
- 作成時刻
- 起点（手動、AI、レビュー）
- 現在版かどうか
- 差分表示ボタン
- 復元ボタン

履歴はファイルごとに絞り込む。プロジェクト全体の版一覧は今回作らない。

### 差分表示

最低限、次を提供する。

1. 現在の本文と選択した過去版
2. 選択した2つの過去版

差分表示は既存のMarkdown表示・ブロック単位の考え方と整合させる。差分のためにGitを導入しない。既存の差分ユーティリティが使える場合は再利用し、同じ表示規則を新規に二重実装しない。

差分画面から本文を直接編集する必要はない。まずは閲覧専用の比較画面とする。

### 復元

復元は現在本文を過去版で無条件に上書きする操作にしない。

1. 現在ディスク上の本文を読み直す
2. 現在本文が画面の基準本文から変わっていれば、復元を止めて確認を出す
3. 現在本文を「復元前バックアップ」として新しい版に保存する
4. 復元対象の本文を新しい版として保存する
5. その本文をディスクへ書き込む
6. キャッシュと表示を更新する

復元後に履歴を戻すのではなく、復元自体を新しい出来事として履歴に残す。復元前の内容へ戻る操作も履歴から可能にする。

保存前のディスク内容が画面の基準本文と異なる場合は、外部変更を破棄してはならない。MVPでは3者マージをせず、保存を中断して「外部変更があります」と知らせるだけでもよい。

### 台帳・保存場所

既存の台帳とスナップショット保存場所を引き続き使用する。既存データを移行しない。

ただし、単一ファイルの「名前を付けて保存」では履歴が途切れないようにする。

- 既存ファイルを開いた場合は、現在の絶対パスを既存互換の識別子として使う
- 新規メモは、アプリ内部の一時ファイルと内部文書IDを持つ
- 新規メモを別パスへ保存した場合、履歴を新しい識別子へ引き継ぐ
- ファイル移動・名前変更時の履歴維持は、少なくともfudeが実行する操作では保証する

外部でファイルを移動した場合の履歴追跡は今回の対象外とする。

## 単一ファイル仕様

### ユーザー向けの入口

起動画面またはランディング画面に、次の入口を用意する。

- 「フォルダを開く」
- 「Markdownファイルを開く」
- 「新しいメモ」

内部状態の名前は `Workspace` / `SingleDocument` / `Scratch` などでよいが、ユーザーに「モード切替」を強く意識させない。

### 既存Markdownファイル

「Markdownファイルを開く」ではファイル選択ダイアログを開く。Tauriのファイルドロップを使う場合は、ウィンドウ設定とイベント処理を確認する。

単一ファイル表示では、以下を行う。

- ファイルツリーを非表示にする
- 文書名と保存先を上部に表示する
- 既存の編集、検索、レビュー、版履歴を使用できるようにする
- 相対画像・相対リンクはファイルの親ディレクトリを基準に解決する
- 「このファイルのあるフォルダをワークスペースとして開く」を提供できるようにする

初期実装では複数の単一ファイルをタブで同時に管理しない。別ファイルを開いた場合は現在文書を切り替える。

### 新しいメモ

「新しいメモ」は保存先未定のMarkdown文書として開始する。

- アプリのデータディレクトリ配下に一時Markdownとして自動保存する
- アプリ終了・クラッシュ後に復元できる
- 一時保存中であることを表示する
- 「名前を付けて保存」で任意の保存先を選べる
- 保存後は通常の単一ファイルとして扱う
- Markdown本文以外の独自形式を保存しない

一時メモの一覧表示・削除・復元は最低限必要だが、タグや分類は今回作らない。

### ファイル保存

既存ファイルの自動保存挙動は維持する。ただし、保存処理は次を満たすこと。

- 書き込み前にディスク上の内容が基準本文から変わっていないか確認する
- 外部変更がある場合は無言で上書きしない
- 保存失敗時は本文を失わず、再試行できる状態にする
- 単一ファイルからワークスペースへ移行しても本文キャッシュを失わない

## 推奨する内部API

名称は既存規約に合わせてよいが、責務は分離する。

### バージョン

- `create_version(file, text, label, origin)`
- `list_versions(file)`
- `read_version(version_id)`
- `diff_versions(left_id, right_id)`
- `restore_version(file, version_id)`

### 文書ソース

- `open_file(path)`
- `open_scratch()`
- `save_as(source, path)`
- `close_document()`

既存のフォルダ向け `useWorkspace` を無理に単一ファイル用条件分岐だらけにしない。ファイル列挙・読み書き・監視・保存先の責務を必要に応じて分離する。

## UI配置

既存の本文編集画面を主画面として維持する。

- 本文上部のツールバーに「版を保存」「履歴」を追加
- 履歴は右ペインまたは下部パネルで表示
- 版を選択すると「現在との差分」「この版から復元」を表示
- 単一ファイル時はファイルツリーを隠し、文書ヘッダーを表示
- 新規メモ時は「一時保存中」「保存先を決める」を表示

新しい画面を丸ごと別に作らず、既存のテーマ・通知・キーボード操作・表示幅を再利用する。

## 実装順

1. 既存版データとCLIの互換性を固定するRustテストを追加
2. 手動版作成・一覧・本文取得のRust関数／Tauriコマンドを追加
3. 履歴パネルと手動保存UIを追加
4. 既存版との差分表示を追加
5. 復元と復元前バックアップを追加
6. 単一既存ファイルのオープンを追加
7. 新規メモと一時保存を追加
8. 名前を付けて保存と履歴引き継ぎを追加
9. 外部変更時の保存前ガードを追加
10. 実機確認とドキュメント更新

バージョニングと単一ファイルの両方を一度に大規模改修しない。まず既存フォルダ内ファイルで版管理を完成させ、その後に単一ファイルの入口を追加する。

## テスト要件

### Rust

- 同じ内容のスナップショットが重複しない
- `Checkpoint` の版が正しく記録される
- 版一覧が新しい順になる
- ラベル・origin・時刻がラウンドトリップする
- 既存CLIの版一覧が変わらない
- 過去版の取得に失敗した場合、安全なエラーになる
- 復元前バックアップが作成される
- 復元に失敗しても現在本文が壊れない

### Frontend

- 履歴パネルを開閉できる
- 手動保存で版が増える
- 同じ本文を保存しても重複表示されない
- 現在版と過去版の差分が表示される
- 復元後に本文・キャッシュ・履歴が一致する
- 単一ファイルを開いて編集・保存できる
- 相対画像・相対リンクが親ディレクトリ基準で解決される
- 新規メモが再起動後に復元できる
- 名前を付けて保存後も履歴が残る

### 実機確認

1. 既存のMarkdownファイルを単独で開く
2. 編集して手動で版を保存する
3. 複数の版を作り、差分を確認する
4. 過去版へ復元する
5. 復元前の版へ再度戻れることを確認する
6. 新しいメモを作り、アプリを再起動して復元する
7. 新しいメモを任意の場所へ保存する
8. 外部エディタで変更してから保存し、無言で上書きされないことを確認する

- 手動保存・履歴閲覧・差分確認・復元がGUIだけで完結する
